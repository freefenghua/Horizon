### [AgentHop：用配对码让跨机器 AI Agent 直接对话](https://www.woshipm.com/ai/6478511.html) ⭐️ 4.0/10

AgentHop 是一款让两台没有公网 IP 的电脑上、来自不同厂商的 AI Agent 直接对话的工具，通过一个配对码建立加密中继通道，可接入 Claude Code、Codex、Cursor、Gemini CLI 和 grok，并以 MCP 工具形式提供创建房间、加入、发送消息、等待回复、加密传文件和查看状态等能力。它解决的是跨机器协作中需要人工复制上下文、粘贴消息、再回传结果的低效问题，让 Agent 负责交换版本、复核结果、传递文件和同步状态。文章给出了三步接入流程（安装单文件版本、注册为 MCP 服务、创建或加入房间）以及典型协作流程，并说明配对码由房间地址和随机密钥组成，中继只能看到通信时间、数量和大小，无法读取消息与文件内容。需要注意的是，该文是技术工具操作说明，未提供任何增长、营销或用户获取相关的指标、案例或可复制战术，因此对增长从业者而言相关性有限。

rss · 人人都是产品经理 · 10月15日 03:16

**「AI 技术点」** AgentHop 通过 MCP（Model Context Protocol）把跨机器 Agent 协作封装成标准工具，并用配对码中的随机密钥建立端到端加密的中继通道，使不同厂商的 Agent 能在无需公网 IP 的情况下交换消息与文件。

**「增长影响」** 源内容未报告任何增长指标、转化数据或商业结果，仅描述工具的技术能力与使用方式，因此无法评估其对获客、留存或转化的影响。

**「可借鉴点」** 若团队内部存在多台机器、多厂商 Agent 协作场景，可评估用 AgentHop 这类 MCP 工具替代人工复制粘贴上下文的流程，但需注意其无前向保密、中继可能延迟消息，重要协作应额外核对公钥指纹。

### [政务产品如何切入 AI Agent 任务执行](https://www.woshipm.com/ai/6478505.html) ⭐️ 4.0/10

文章围绕 OpenAI 发布的 Agents API 公测版展开，指出开发者现在可以让 Agent 持续执行复杂任务、调用不同工具，并把一项工作拆分给多个子智能体并行处理。作者认为，政务产品接入大模型的难点不在模型本身，而在于把业务拆成可执行步骤，并让每一步可被检查和追溯。文章提出政务 AI 应从高频、规则清晰、结果可验证的小任务切入，例如材料预审、收件助手或窗口辅助助手，并以材料退回率、群众咨询次数、单件业务处理时长等业务指标衡量效果。需要说明的是，全文属于产品设计层面的概念性讨论，未提供具体公司案例、前后对比数据或可复现的增长实验。

rss · 人人都是产品经理 · 10月15日 03:15

**「AI 技术要点」** 文章讨论的是 OpenAI Agents API 公测版，其能力在于让 Agent 持续执行复杂任务、调用不同工具，并将任务拆分给多个子智能体并行处理，相比过去调用模型加拼接提示词的方式更偏向任务执行。作者强调，政务场景中真正的工作量在于把业务流程拆解为可执行步骤，并让 Agent 在授权范围内连接真实业务系统、查询事项、调用接口和保存办理进度。

**「增长影响」** 文章未给出任何量化结果或增长数据，仅提出应以材料退回率是否下降、群众咨询次数是否减少、工作人员处理一件业务的时间是否缩短作为衡量指标。这些指标属于作者建议的评估方向，而非已验证的成效，且文章未说明适用规模、地区或行业条件。

**「可执行启示」** 若要在政务或流程密集型业务中落地 Agent，不要一上来做“超级 Agent”，而应选择一个高频、规则清晰、结果可验证的小任务（如材料预审或收件助手）先跑稳，并用材料退回率、咨询次数、单件处理时长等业务指标而非模型能力指标来衡量效果。

### [Perplexity CEO 访谈：收入同比增长 5 倍，企业端增速超过个人专业用户](https://www.woshipm.com/ai/6478493.html) ⭐️ 4.0/10

Perplexity 创始人兼 CEO Aravind Srinivas 在 Sourcery 的访谈中表示，公司收入同比增长 5 倍，企业端今年的增长甚至超过个人专业用户。他把公司定位为“模型中立的编排平台”，不绑定任何模型、芯片或客户规模，并认为下一轮美国经济增长可能更多来自小而强的 AI-native 公司。在成本层面，他给出粗略估算：聊天场景放到本地运行的成本约为数据中心的 30 倍，但当上下文长到 10 万量级时，数据中心的成本优势只剩约 3 倍甚至接近 1 倍，因此常驻、个性化的 agent 更适合本地算力。他还提到一位“一人公司”用户每年在 Perplexity Computer 上花费超过 100 万美元，靠该工具自动化制作 newsletter 年赚 300 万美元。需要说明的是，这些数字均为其个人说法，访谈中未提供第三方验证，且他本人也承认部分估算是“信封背面”的粗略计算。

rss · 人人都是产品经理 · 10月15日 03:07

**「AI 技术要点」** Perplexity 的核心技术思路是“模型中立编排”：在真实知识工作与研究场景中，同时调用多个前沿模型，由 harness（编排层）自动处理模型选择、上下文管理和本地/云端路由，用户无需了解哪个模型擅长什么。其本地算力方案基于开源权重模型，可在 Apple 芯片等消费级设备上运行最多约 1000 亿参数的模型，并与 Nvidia、Apple 合作实现本地与云端之间的自动切换。

**「增长影响」** 访谈披露的唯一硬性增长数据是收入同比增长 5 倍，且企业端增速超过个人专业用户，但未给出绝对收入规模、客户数量或留存指标。其增长机制被描述为“递归”而非网络效应：收入不直接长在用户数量上，而是长在用户的收入上——用户用 Perplexity 赚得越多，Perplexity 的收入也越高，例如那位年付超 100 万美元、年赚 300 万美元的一人公司用户。该模式更接近支付公司的价值捕获逻辑，但访谈未提供可验证的转化率、留存率或 CAC 数据，且“小公司驱动下一轮经济增长”被明确表述为假设而非结论。

**「可借鉴之处」** 在评估 AI 产品的增长质量时，与其只看用户规模，不如追踪“用户使用深度”与“用户自身收入”之间的关联，把每个用户的使用深度和其业务成果作为核心指标，而非单纯追求用户数量。
