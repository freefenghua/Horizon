### [决策模型评估调优：阈值比默认 0.50 更关键](https://hamel.dev/blog/posts/decision-model-evals/) ⭐️ 4.0/10

本文介绍如何为自动化评估中的决策模型（decision models）调优判定阈值，而不是沿用 API 默认的 0.50。作者用 100 条公寓租赁代理的对话 trace 做二分类失败检测，对比了 Jev 1.13、Perplexity Decider 1.1 27B、Liquid d1 与 d1-ultra、Cloudflare Clef Flash、OpenAI Decisions（GPT-6 Luna）等模型的表现与 API 成本。结果显示，默认阈值会显著压低效果，按 F1 并约束精确率与召回率均不低于 80%来调优阈值后，部分模型能达到业务可用标准。文章强调阈值选择应服务于业务目标（如告警系统更看重精确率），并建议用分层五折交叉验证在训练集上选阈值、在验证集上评估。对增长从业者而言，这提供了一个可复用的方法：用低成本决策模型替代 LLM 评审做大规模自动化质检，但必须先按业务代价调阈值。

rss · Hamel Husain · 10月20日 07:00

**「AI 技术要点」** 决策模型是一类快速、低成本的分类模型，对每条输入返回 0 到 1 的失败概率，再由阈值转成通过/失败判定。作者的核心做法是基于已保存的模型分数与人工标注，用交叉验证搜索最优阈值（如最大化 F1，同时约束精确率与召回率下限），而非直接使用默认 0.50。

**「增长影响」** 该案例未报告转化率、留存或获客成本等增长指标，属于技术评估范畴。其可迁移的价值在于成本结构：决策模型被定位为 LLM 评审的低成本替代方案，可用于大规模自动化质检；但文中未给出具体成本节省数字，仅说明成本按 token 用量与厂商价格计算。

**「可执行启示」** 若用自动化评估监控用户体验或转化漏斗中的失败环节，不要直接采用默认 0.50 阈值：先用带标注样本按业务代价（精确率与召回率的最低要求）调优阈值，再比较不同模型的成本与效果。
