### [TypeSafe AI 发布 Jev：不生成文字、只输出结构化概率决策的模型](https://www.woshipm.com/ai/6466421.html) ⭐️ 6.0/10

TypeSafe AI 发布了名为 Jev 的模型，它不生成任何文字，而是接收状态与一组带有限选项的问题，在几百毫秒内并行输出带校准概率值的结构化决策，支持是/否（nule）、多选（choice）和打分（score）三种问题类型。该模型由 ChatGPT 联合发明人之一、RLHF 重要贡献者 Diogo Almeida 创立，旨在解决大语言模型在自动化流程中不可靠的问题——同一问题答案不一致、结构化输出偶尔幻觉出 schema 外字段、置信度过度自信等。据文章，Jev 比现有语言模型快 20 到 200 倍、便宜 40 到 400 倍，端到端响应时间在 70 毫秒到 500 毫秒之间，output token 免费；Vercel 用它替换 Gemini 2.5 Flash 做分类后速度提升 6 倍且准确率拉满，用 Jev 玩《毁灭战士》连续跑一小时成本仅 7 美元。对增长从业者而言，这意味着意图识别、智能路由、内容审核、AI 输出验证等高频自动化决策环节，可能获得更快、更便宜且类型安全的新基础设施。需要说明的是，该文属于产品发布介绍，缺乏增长场景下的具体转化率、留存或 CAC 等指标与可复制的增长案例。

rss · 人人都是产品经理 · 9月19日 01:33

**「AI 技术要点」** Jev 采用非自回归架构，不生成 token，而是并行计算所有问题的所有答案，输出落在预设选项内、带校准概率值的结构化结果，被 TypeSafe AI 称为 System One Model。其训练方法为 RLCD（Reinforcement Learning for Calibrated Decisions，用于校准决策的强化学习），目标不是人类偏好（RLHF）或可程序化验证的奖励（RLVR），而是让模型输出的置信度与实际准确率有意义地对应。

**「增长影响」** 文章未提供增长场景下的转化率、留存或 CAC 等指标，因此无法量化其对增长结果的影响。可确认的机制性收益是：在分类、路由、审核、验证等高频决策环节，Jev 以 70–500 毫秒延迟和极低成本替代大语言模型调用，从而降低延迟与成本、减少因类型错误导致的链路故障。文中案例包括 Vercel 分类任务速度提升 6 倍、准确率拉满，以及 Sentry 内部 Slack 机器人用 Jev 两个问题替代长 prompt 做模型路由。这些属于工程效率与可靠性层面的证据，而非增长指标。

**「可执行启示」** 增长团队可优先在意图识别、请求路由、内容审核和 AI 输出验证这四个高频、低延迟要求的环节试点 Jev 这类结构化决策模型，用带置信度的输出替代长 prompt 判断，并在置信度低时设置兜底逻辑。

### [SAP 收「代理税」、Salesforce 全开放：AI Agent 平台生意殊途同归](https://www.woshipm.com/ai/6466441.html) ⭐️ 6.0/10

SAP 与 Salesforce 在 AI Agent 生态上采取了截然相反的开放策略：SAP 于今年 4 月收紧 API 政策，外部 AI 智能体不能直连接口，必须走自家助手 Joule，集成网关开始按调用次数计费，被业内称为「代理税」；Salesforce 则把整个平台能力拆成 60 多个工具、30 多项技能，让销售可以全程不打开 CRM。文章指出，两家表面上一松一紧，最终都指向同一门生意——帮企业管住 agent，即「治理即产品」，微软 Agent 365 按每人每月 15 美金收费，上线两个月登记 agent 接近 4000 万个。文章同时提醒，按用量、动作、结果计费的新账单模式正在给企业带来意外支出，78% 的 IT 负责人撞上过意外账单，61% 的人为没计划的软件支出砍过项目。对增长从业者而言，这意味着平台渠道成本结构正在从「买工具」转向「按动作付费」，需要重新评估 AI 供应商的计费风险与议价空间。

rss · 人人都是产品经理 · 9月18日 07:30

**「AI 技术要点」** 文章涉及的核心技术机制是 AI Agent 的接口治理与调用计量：SAP 通过 API 网关限制外部智能体直连、强制走 Joule 助手并记录调用次数，Salesforce 则通过 API、MCP 工具和命令行把平台能力暴露给外部 agent。配套的治理层（如微软 Agent 365、ServiceNow 控制塔）用于管理 agent 的身份、权限、执行流水和账单。

**「增长影响」** 文章未提供与转化率、留存率直接挂钩的增长指标，但给出了若干可参考的规模数据：SAP 自家 AI 在生产环境的客户采用率仅 3%（DSAG 调查，SAP 对样本量有异议）；Salesforce 自定义智能体挂在 Slack 上从 1 月起涨了三倍；ServiceNow 客服台 89% 的问题已由 AI 处理，8400 个企业客户续费率 98%；Workday 平台上财年跑了 17 亿次 AI 动作。这些数据反映的是平台侧的采用与计费规模，而非增长结果，需谨慎解读。

**「可执行启示」** 在采购或集成 AI Agent 能力时，应优先确认计费单位（按调用次数、动作还是结果）以及超额部分的触发条件，因为多数变动条款写在厂商文档而非合同里，改一版价就换一档；同时可要求按结果付费或设置用量上限，以对冲账单失控风险。

### [详情页秒变 16 秒宣传片：豆包+Flova AI 电商视频工作流实测](https://www.woshipm.com/ai/6466451.html) ⭐️ 6.0/10

作者实测了用豆包工作（Doubao）连接 Flova AI，把一张写有商品参数与卖点的电商详情页，转化为一支 16 秒商品宣传短片的完整流程。具体链路为：先识别详情页中的商品主图、参数与卖点，再依次生成参考视觉、四镜分镜、配乐与环境音，最后在时间线中合成并导出 1920×1080、30fps、H.264 视频与 AAC 立体声音轨的 MP4。成片围绕“微光 L1 氛围灯”的露营夜景场景，四段镜头分别承担环境建立、无级调光、提手便携和续航收尾四个卖点，且暖白机身、焦橙提手、黑色底座与圆柱造型在主要镜头中保持基本一致。作者强调 Flova 的价值不在于单次生成，而在于把原本分散的确认节点串成可检查、可修改、可交付的工作流，让反馈能落到具体镜头而非整片重做。需要说明的是，原文未提供转化率、留存、CAC 等硬性效果数据，且内容在展示结果前已截断，因此该案例更接近可复现的流程演示而非已验证的增长结果。

**「AI 技术要点」** 该流程使用豆包工作作为入口，通过其技能与连接器页面关联 Flova AI，由 Flova 承担从商品资料识别、参考视觉生成、四镜分镜、配乐与环境音生成到时间线合成与导出的多步骤生成式视频工作流。作者通过一段结构化提示词锁定成品规格（15 秒、16:9）、卖点、产品外观、镜头数量、确认顺序与声音要求，并在正式生成前先确认参考图与分镜，以降低方向性返工。
